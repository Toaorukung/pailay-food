# Pailay Food — ระบบสั่งอาหารผ่าน QR สำหรับพูลวิลล่า

แขกสแกน QR ที่ติดในวิลล่า → สั่งอาหาร → ชำระด้วย PromptPay → อัปสลิป → พนักงานยืนยัน → เซสชันปิด
ลิงก์เดิมกลายเป็นใบเสร็จอย่างเดียว สั่งเพิ่มไม่ได้ ต้องสแกนใหม่

- **Frontend/Backend**: Next.js 15 (App Router) + TypeScript + Tailwind v4
- **ฐานข้อมูลหลัก**: Google Sheets
- **ชั้นความเร็ว**: Upstash Redis (แคช เซสชัน ตะกร้า ออเดอร์ คิวเขียน)
- **ไฟล์**: Vercel Blob (สลิป + รูปเมนู)
- **ภาษา**: ไทย / English / 中文

---

## ทำไมถึงเร็วทั้งที่ใช้ Google Sheet

Google Sheets API จำกัดราว **300 read/นาที และ 60 write/นาที ต่อโปรเจกต์** และแต่ละคอลใช้เวลา 300–800 ms
ถ้ายิงตรงทุก request ที่ 10–50 โต๊ะพร้อมกัน จะได้ HTTP 429 และหน้าเว็บอืดทันที

ระบบนี้จึงแยกเป็น 3 ชั้น:

| ชั้น | เก็บอะไร | ใครแตะ |
|---|---|---|
| **แคชเมนู** (Redis) | เมนู หมวดหมู่ สารก่อภูมิแพ้ ตัวเลือก การตั้งค่า — ก้อนเดียว | ทุก request ของแขก |
| **Hot store** (Redis) | เซสชัน ตะกร้า ออเดอร์ที่เปิดอยู่ การชำระเงิน | ทุก read/write ของแขก |
| **Google Sheet** | บันทึกถาวรทั้งหมด | คิวเขียนแบบ batch เท่านั้น |

ผลลัพธ์: **การเปิดเมนู 1 ครั้ง = 0 Sheets call** ในสภาวะปกติ และ **ออเดอร์ 50 รายการ = 1 API call** ไม่ใช่ 50

ตรวจสอบเองได้ — `npm run loadtest` จะยิงโหลดจริงแล้วรายงานจำนวน Sheets call ที่เกิดขึ้นจริง
(ตัวนับอยู่ใน Redis key `metrics:sheets:*` เขียนโดย `src/lib/sheets/client.ts`)

**เพดานของสถาปัตยกรรมนี้อยู่ราว 100 โต๊ะพร้อมกัน** เกินกว่านั้นควรย้ายไป Postgres แล้ว sync ลง Sheet เพื่อดูรายงานแทน

## ติดตั้ง

### 1. ติดตั้ง dependencies

```bash
npm install
```

### 2. Google Sheet + Service Account

1. สร้าง Google Sheet เปล่า 1 ไฟล์ คัดลอก id จาก URL
   `https://docs.google.com/spreadsheets/d/`**`<SHEET_ID>`**`/edit`
2. [Google Cloud Console](https://console.cloud.google.com) → สร้างโปรเจกต์ → เปิดใช้ **Google Sheets API**
3. **Credentials → Create Credentials → Service Account** → Keys → **Add Key → JSON**
4. **แชร์ Sheet ให้อีเมลของ Service Account เป็น Editor** (ขั้นนี้ลืมบ่อยที่สุด — ถ้าลืมจะได้ error 403)
5. แปลงไฟล์ JSON เป็น base64:

   ```powershell
   # Windows PowerShell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("key.json")) | Set-Clipboard
   ```
   ```bash
   # macOS / Linux
   base64 -w0 key.json
   ```

### 3. Upstash Redis + Vercel Blob

- **บน Vercel**: Storage → Upstash Redis และ Storage → Blob — ตัวแปรจะถูกฉีดให้อัตโนมัติ
- **ในเครื่อง**: สมัคร [upstash.com](https://upstash.com) (ฟรี) แล้วคัดลอก REST URL + Token

### 4. สร้างไฟล์ `.env.local`

```bash
cp .env.example .env.local
```

สร้าง secret แต่ละตัวด้วย `openssl rand -base64 32` (หรือ `[Convert]::ToBase64String((1..32|%{Get-Random -Max 256}))` บน PowerShell):

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `TABLE_SECRET` | เซ็นลิงก์ใน QR — **เปลี่ยนแล้ว QR ที่พิมพ์ไปแล้วทั้งหมดใช้ไม่ได้** |
| `SESSION_SECRET` | เซ็นคุกกี้เซสชันแขกและ JWT ของแอดมิน |
| `CRON_SECRET` | ป้องกัน `/api/cron/*` จากการเรียกจากภายนอก |
| `PROMPTPAY_ID` | เบอร์มือถือ 10 หลัก หรือเลขบัตรประชาชน/ผู้เสียภาษี 13 หลักที่รับเงิน |

### 5. สร้างโครงสร้าง Sheet + ข้อมูลตัวอย่าง

```bash
npm run seed
```

สคริปต์จะสร้างแท็บทั้ง 14 แท็บ เขียนหัวคอลัมน์ แล้วใส่ **เมนูจริงของไปเล วิลล่า**
(109 รายการ 22 หมวด 68 กลุ่มตัวเลือก 244 ตัวเลือก) พร้อมบัญชีแอดมินเริ่มต้น
จากนั้นจะพิมพ์ **ลิงก์ QR ของ Villa 1** ออกมาให้

เมนูอยู่ใน [`scripts/menu-data.ts`](scripts/menu-data.ts) — ถอดมาจากบอร์ดเมนูใน `food/detail/`
แก้ไฟล์นั้นแล้วรัน seed ใหม่บนชีตเปล่าได้ หรือแก้ผ่านหน้าแอดมินหลังจากนี้

รันซ้ำได้ปลอดภัย — แท็บที่มีข้อมูลอยู่แล้วจะถูกข้าม ใช้ `npm run seed -- --bare` ถ้าต้องการแค่โครงสร้าง

> **ต้องแก้ก่อนใช้จริง**
> - **พิกัดวิลล่า** — seed ใส่พิกัดชะอำแบบกลม ๆ ไว้ทั้ง 6 หลัง ตั้งหมุดจริงในหน้า `/admin/tables` ก่อนพิมพ์ QR
> - **ราคาที่ยังไม่ยืนยัน** — กลุ่ม "กุ้ง + หมึก" บนบอร์ดไม่มีราคากำกับ ตั้งไว้ที่ 250 บาทเป็นค่าเริ่มต้น
> - **รายการถามราคา** — ปูนึ่ง กุ้งแม่น้ำ กุ้งลายเสือ กุ้งแช่บ๊วย ปลาสำลี ปลาเก๋า ตั้งเป็น `price_on_request`
>   แขกสั่งได้ แต่พนักงานต้องใส่ราคาจริงในหน้าครัวหลังชั่ง และแขกเช็คบิลไม่ได้จนกว่าจะใส่ครบทุกบรรทัด

### 6. รัน

```bash
npm run dev
```

## Deploy บน Vercel

1. push โค้ดขึ้น Git → Import ใน Vercel
2. Storage → เพิ่ม **Upstash Redis** และ **Blob**
3. ใส่ Environment Variables ที่เหลือให้ครบตาม `.env.example`
4. ตั้ง `NEXT_PUBLIC_APP_URL` เป็นโดเมนจริง **แล้วรัน `npm run seed` ใหม่** เพื่อให้ QR ชี้โดเมนถูก
5. `/admin/tables` → **พิมพ์ QR ทุกวิลล่า** → ตัดแล้วติดในห้อง

> **Cron**: `vercel.json` ตั้ง `/api/cron/sync` ไว้ทุกนาที — แผน Hobby รันได้แค่วันละครั้ง
> ไม่กระทบการใช้งาน เพราะการเขียนลง Sheet เกิดขึ้นทันทีหลังทุก request ผ่าน `after()` อยู่แล้ว
> cron เป็นแค่ตาข่ายรองสำหรับ retry

## กลไกสำคัญ

### เซสชัน — "เช็คบิลแล้วลิงก์เดิมสั่งต่อไม่ได้"

QR ที่พิมพ์เป็นแบบ **ถาวรต่อวิลล่า** — `/t/<tableId>?k=<hmac>`

1. สแกน → ตรวจ HMAC → สร้าง `sessionId` สุ่ม 128 บิต → ตั้งคุกกี้ → redirect ไป `/s/<sessionId>`
2. หลายมือถือในวิลล่าเดียวกันสแกนแล้วเข้าร่วมเซสชันเดิม (แชร์ตะกร้า แชร์บิล)
3. แอดมินยืนยันสลิป → เซสชัน `CLOSED`
4. `/s/<sessionId>` เดิมยังเปิดดูใบเสร็จได้ แต่ **API ที่แก้ข้อมูลทุกตัวคืน 403**

การป้องกันมี 2 ชั้น ตรวจทุกครั้งที่ฝั่ง server ไม่ใช่แค่ตอน render:

| ชั้น | กันอะไร |
|---|---|
| `status === 'OPEN'` | เซสชันที่ปิดแล้ว — ต่อให้ยิง `curl` ตรงก็ไม่ผ่าน |
| คุกกี้ต้องตรงกับ sessionId ใน URL | คนที่ได้ลิงก์ต่อมาแต่ไม่ได้สแกน QR ในห้อง |

ทั้งสองอยู่ใน `requireSession()` ([src/lib/session.ts](src/lib/session.ts)) ซึ่งทุก route ที่แก้ข้อมูลเรียกเป็นบรรทัดแรก

### เตือนแพ้อาหาร

- แขกเลือกสิ่งที่แพ้ตอนเปิดเซสชัน (ข้ามได้ แก้ทีหลังได้)
- เมนูที่ตรงกันขึ้นขอบแดง + badge; ที่ปนเปื้อนข้ามได้ขึ้นสีเหลือง
- กดเพิ่มลงตะกร้า → **dialog บล็อก ต้องติ๊กรับทราบ** และ **server ปฏิเสธถ้าไม่มี ack** (`ALLERGEN_ACK_REQUIRED`)
- ตั๋วครัวขึ้นแถบแดงบนสุด และระบุรายบรรทัดว่าแขกยืนยันทั้งที่แพ้ ← จุดนี้คือสิ่งที่ปกป้องแขกจริง

### ค้นหา

ค้นได้ทั้ง **ชื่อ / หมวดหมู่ / ส่วนผสม / แท็ก / คำอธิบาย** ทั้ง 3 ภาษาพร้อมกัน ทำงานบน client ล้วน — ไม่ยิง network เลย

ภาษาไทยไม่มีเว้นวรรค การ tokenize จึงใช้ไม่ได้ (`ต้มยำกุ้ง` คืออักขระต่อเนื่องที่มี `กุ้ง` อยู่ข้างใน)
ระบบใช้ **scored substring** บน index ที่ normalize แล้ว พร้อม fallback ที่ตัดวรรณยุกต์ออกเพื่อทนพิมพ์ผิด

### ราคา

ไคลเอนต์ส่งแค่ `menuId` + `optionIds` + `qty` + `note` — **ไม่มีฟิลด์ราคาใน request เลย**
ราคาถูก resolve ใหม่จากแคชเมนูทุกครั้ง และ resolve อีกรอบตอนกดส่งออเดอร์
(เผื่อครัวเพิ่งประกาศของหมดหรือแอดมินเพิ่งเปลี่ยนราคา)

### หมายเหตุ 500 ตัวอักษร

จำกัดที่ `maxLength` ของ textarea **และ** zod `.max(500)` ฝั่ง server
ตัดอักขระควบคุมทิ้ง แต่ไม่ escape HTML — React escape ตอน render อยู่แล้ว การ escape ซ้ำจะทำให้ตั๋วครัวอ่านเพี้ยน

### Geofence

เตือนอย่างเดียว ไม่บล็อก — ตามที่ตั้งใจไว้
GPS ใต้หลังคาวิลล่าคลาดเคลื่อนหลักร้อยเมตรเป็นเรื่องปกติ และ iOS ปฏิเสธสิทธิ์บ่อยพอที่จะทำให้แขกที่จ่ายเงินสั่งอาหารไม่ได้
**ตัว QR ที่ติดอยู่ในห้องคือหลักฐานการอยู่จริงที่ดีกว่า GPS อยู่แล้ว**

เบราว์เซอร์ส่งพิกัดดิบมา — **server คำนวณระยะเอง** ไม่รับตัวเลขระยะจาก client
ระบบยังเผื่อค่า accuracy ที่มือถือรายงานเข้าไปในรัศมีที่ยอมรับ เพื่อไม่ให้เตือนแขกที่ยืนอยู่ในห้องจริง

### ชำระเงิน

PromptPay QR สร้างฝั่ง server โดย **ฝังยอดเงินไว้ในตัว payload** — พนักงานจึงเทียบตัวเลขเดียวกับตัวเลขเดียว

การอัปโหลดสลิปผ่านขั้นตอนนี้ทุกไฟล์:

1. บีบรูปในเบราว์เซอร์ก่อนส่ง (กล้องมือถือให้ไฟล์ 8MB, wifi วิลล่าไม่ไหว)
2. ตรวจ **magic bytes จริง** — ไม่เชื่อ `Content-Type` ที่ client ส่งมา
3. re-encode ผ่าน sharp — ล้าง EXIF (ซึ่งมีพิกัด GPS ของแขก) และ payload ที่แนบท้ายมา
4. จำกัด 5MB, 5 ครั้ง/เซสชัน/10 นาที
5. เก็บใน Blob ด้วย path สุ่ม **และไม่เคยส่ง URL นั้นให้เบราว์เซอร์** — แอดมินดูผ่าน proxy ที่ต้อง auth

> **ข้อจำกัดที่ต้องรู้**: ยืนยันด้วยตาคน สลิปปลอมผ่านได้ถ้าพนักงานเผลอ
> ระบบลดความเสี่ยงด้วยการวางยอดที่ควรได้รับตัวโตข้างรูปสลิป และบันทึกชื่อคนกดอนุมัติไว้ในทั้งตัว payment และ audit log
> ถ้าต้องการอัตโนมัติ ต่อ SlipOK/EasySlip เพิ่มได้ โดยแตะแค่ `attachSlip()` และ route อนุมัติ

## สิทธิ์ผู้ใช้แอดมิน

| Role | ทำอะไรได้ |
|---|---|
| `STAFF` | ดูภาพรวม, จัดการออเดอร์ในครัว, ตรวจสลิป, ดูเซสชัน |
| `MANAGER` | + แก้เมนู หมวดหมู่ สารก่อภูมิแพ้ วิลล่า/QR, ดูรายงาน, ปิดเซสชัน |
| `OWNER` | + ตั้งค่าร้าน, ดูประวัติการแก้ไข |

middleware กันแค่หน้าเว็บ — **ทุก API route ตรวจ role ซ้ำเอง** เพราะการซ่อนปุ่มไม่ใช่การจำกัดสิทธิ์

unit test ครอบคลุมเฉพาะสิ่งที่ **ผิดแบบเงียบ ๆ ได้**: การคิดเงิน การจับคู่สารก่อภูมิแพ้ กฎการค้นหาภาษาไทย และการตรวจไฟล์อัปโหลด

e2e ตรวจสิ่งที่ unit test ตรวจไม่ได้ ที่สำคัญที่สุดคือ:
**ยิง `POST /api/s/<id>/order` ด้วยคุกกี้ที่ถูกต้องทุกประการบนเซสชันที่ปิดแล้ว ต้องได้ 403** ไม่ใช่แค่ปุ่มหายไปจากหน้าจอ

## แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ |
|---|---|
| `Sheets 403` | ลืมแชร์ Sheet ให้อีเมลของ service account |
| `Sheets 429` | มีอะไรอ่าน Sheet ตรง ๆ ไม่ผ่านแคช — ดู log `[sync]` และ `[menu]` |
| หน้าแอดมินเด้งกลับ login วน | `SESSION_SECRET` ไม่ตรงกันระหว่าง middleware กับ runtime |
| QR สแกนแล้วขึ้น "ลิงก์ไม่ถูกต้อง" | `TABLE_SECRET` เปลี่ยนหลังพิมพ์ QR — ต้องพิมพ์ใหม่ |
| ไม่ขึ้นขอตำแหน่ง | ไม่ได้เปิดผ่าน HTTPS |
| Dashboard ขึ้น "บันทึกลง Sheet ล้มเหลว" | ดูแท็บ `SyncDeadLetter` — ระบบยังรับออเดอร์ได้ปกติ แต่ข้อมูลยังไม่ลงชีต |
